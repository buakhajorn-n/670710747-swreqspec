# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

Spec: `SPEC-BKG-001`  
ไฟล์อ้างอิง: `specs/001-booking/spec.md` (Draft v2)  
สถานะ: รอทีมตรวจแผน

## 1. สรุปแนวทาง

ฟีเจอร์นี้ให้ผู้รับบริการที่ยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพเพื่อจองคิว (FR-BKG-01, FR-BKG-04)
ระบบจะแสดงช่วงเวลาว่างและจำนวนที่นั่งภายใน 30 วัน และคำนวณใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-01, FR-BKG-06)
ระบบจะตรวจคิวเดิมและตรวจที่นั่งซ้ำในจังหวะยืนยัน เพื่อป้องกันการจองซ้อน (FR-BKG-02, FR-BKG-03)
เมื่อสำเร็จ ระบบจะบันทึกการจอง ตัดที่นั่ง ออกหมายเลขคิว และแสดงหมายเลขคิว โดยไม่รอผลการส่งข้อความ (FR-BKG-04, IF-NOT-01)
การเชื่อมต่อภายนอก ความปลอดภัย และ audit log จะทำตาม Constraints และตรวจรับด้วย AC-BKG-01 ถึง AC-BKG-06

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| MySQL | CON-TECH-01 | ใช้เก็บข้อมูลการจอง จำนวนที่นั่ง หมายเลขคิว และ audit log ตามข้อกำหนดที่เกี่ยวข้อง |
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างหน้าจอค้นหาและยืนยันการจอง ตามค่าเริ่มต้นของรายวิชา |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้าง API สำหรับการค้นหาและจอง ตามค่าเริ่มต้นของรายวิชา |
| ระบบคิวส่งข้อความ asynchronous | ทีมเลือกเอง ไม่ได้มาจาก spec | รายละเอียดกลไกคิวและ retry ยังต้องไม่กำหนดเกิน spec; ต้องรองรับ IF-NOT-01 และ NFR-REL-02 |

## 3. โมเดลข้อมูล

| Entity / ตาราง | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `booking` | `id`, `hn`, `package_id`, `service_date`, `time_slot_id`, `queue_number`, `status`, `created_at` | FR-BKG-02, FR-BKG-04, FR-BKG-05 |
| `time_slot` | `id`, `service_date`, `start_time`, `end_time`, `package_id`, `capacity`, `remaining_seats` | FR-BKG-01, FR-BKG-03, FR-BKG-04, FR-BKG-06 |
| `queue_counter` | `service_date`, `reset_at`, `current_number` | FR-BKG-04, ASM-04 |
| `notification_delivery` | `id`, `booking_id`, `channel`, `status`, `retry_due_at` | FR-BKG-05, NFR-REL-02, IF-NOT-01 |
| `audit_log` | `id`, `accessor`, `accessed_at`, `patient_code` | DOM-PDPA-01, AC-BKG-06 |

`booking` ต้องไม่มีฟิลด์เลขบัตรประชาชน โดยใช้ `hn` เป็นตัวอ้างอิงภายในระบบตาม IF-HIS-01 ส่วนผลยืนยันตัวตนจาก IDP และข้อมูลจาก HIS เป็นข้อมูลจากระบบภายนอก ไม่สร้างขอบเขตใหม่เกิน IF-IDP-01 และ IF-HIS-01

## 4. API / หน้าจอ

รายละเอียด method และ path เป็นการเลือกของทีมเอง ไม่ได้มาจาก spec

- `GET /booking/time-slots` รับ `package_id`, ช่วงวันที่ และ HN จากบริบทการยืนยันตัวตน; ส่งวัน ช่วงเวลา และ `remaining_seats` ภายใน 30 วัน (FR-BKG-01, IF-IDP-01, IF-HIS-01)
- `GET /booking/time-slots?package_id=...` เมื่อเปลี่ยนแพ็กเกจ; ส่งผลช่วงเวลาว่างที่คำนวณใหม่ตามแพ็กเกจ (FR-BKG-06)
- `POST /booking` รับ `hn`, `package_id`, `service_date`, `time_slot_id`; ส่งสถานะการจองและ `queue_number` เมื่อสำเร็จ หรือหมายเลขคิวเดิมเมื่อถูกปฏิเสธ (FR-BKG-02, FR-BKG-04)
- `GET /booking/conflicts/{request_id}` รับผลกรณีที่นั่งเต็มระหว่างยืนยัน; ส่งข้อความช่วงเวลาเต็มและช่วงเวลาใกล้เคียง 3 ตัวเลือกจากวันก่อนหน้า วันเดียวกัน หรือวันถัดไป โดยลำดับความใกล้ยังไม่กำหนด (FR-BKG-03, ASM-05)
- หน้าค้นหาช่วงเวลาว่าง รับแพ็กเกจและวัน; แสดงช่วงเวลา จำนวนที่นั่ง และผลที่คำนวณใหม่ (FR-BKG-01, FR-BKG-06)
- หน้ายืนยันการจอง รับช่วงเวลาที่เลือก; แสดงผลสำเร็จ หมายเลขคิว หรือเหตุผลปฏิเสธ (FR-BKG-02, FR-BKG-04)
- หน้าผลช่วงเวลาเต็ม แสดงข้อความแจ้งเตือนและตัวเลือก 3 รายการ โดยไม่แสดงรายการจองที่สร้างขึ้น (FR-BKG-03)

## 7. ลำดับงาน

1. กำหนด schema ของ `booking`, `time_slot`, `queue_counter`, `notification_delivery` และ `audit_log` โดยไม่เก็บเลขบัตรประชาชน (CON-TECH-01, IF-HIS-01, DOM-PDPA-01)
2. เชื่อมบริบทการยืนยันตัวตนและการอ้างอิง HN ก่อนเข้าถึงข้อมูลผู้รับบริการ (IF-IDP-01, IF-HIS-01)
3. สร้าง API และหน้าค้นหาช่วงเวลาว่างภายใน 30 วัน พร้อมจำนวนที่นั่ง (FR-BKG-01, AC-BKG-05)
4. เพิ่มการคำนวณช่วงเวลาว่างใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-06)
5. สร้างการตรวจคิวที่ยังไม่ได้ใช้และการปฏิเสธพร้อมหมายเลขคิวเดิม (FR-BKG-02, AC-BKG-02)
6. สร้าง transaction สำหรับตรวจที่นั่ง บันทึกการจอง ตัดที่นั่ง และออกหมายเลขคิวตาม ASM-04 (FR-BKG-04, AC-BKG-01)
7. เพิ่มการตรวจกรณีที่นั่งเต็มระหว่างยืนยัน และค้นหาตัวเลือกใกล้เคียงจากวันก่อนหน้า วันเดียวกัน หรือวันถัดไป (FR-BKG-03, ASM-05, AC-BKG-03)
8. เพิ่มการส่งข้อความแบบ asynchronous และรายการส่งซ้ำภายใน 5 นาที (FR-BKG-05, AC-BKG-04, IF-NOT-01, NFR-REL-02)
9. เพิ่ม audit log, การรับส่งด้วย TLS 1.2 ขึ้นไป และทดสอบการใช้งานผู้ใช้ใหม่ (DOM-PDPA-01, NFR-SEC-01, NFR-USE-01, AC-BKG-06)

## 8. สิ่งที่ยังไม่ทำ

คำถามเรื่องขอบเขตวันได้คำตอบแล้วและบันทึกเป็น ASM-05 ใน spec: ให้พิจารณาวันก่อนหน้า วันเดียวกัน และวันถัดไป

ส่วนการจัดลำดับว่าเวลาใด “ใกล้เคียง” ที่สุด และวิธีเลือกให้เหลือ 3 รายการยังไม่กำหนด เพราะคำตอบของทีมระบุเฉพาะขอบเขตวัน จึงยังไม่สร้างกติกาส่วนนั้นจนกว่าจะมีการปรับ spec เพิ่ม

รายละเอียด rollback เมื่อการบันทึกการจอง การตัดที่นั่ง หรือการออกหมายเลขคิวล้มเหลว และรายละเอียดประเภทความล้มเหลว/จุดเริ่มนับ retry ยังไม่ถูกเพิ่ม เพราะ spec ยังไม่ได้ระบุเป็น Open Question ที่มี ID ชัดเจน จึงต้องขอให้ทีมปรับ spec ก่อน ไม่เดาแทนทีม (FR-BKG-04, FR-BKG-05, NFR-REL-02)
